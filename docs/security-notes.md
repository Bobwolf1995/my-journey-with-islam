# ملاحظات الأمان - رحلتي مع الإسلام

هذا الملف يوضح أهم قواعد الأمان التي يجب مراعاتها أثناء تطوير منصة "رحلتي مع الإسلام".

## 1. المصادقة

- استخدام Laravel Sanctum في المرحلة الأولى.
- تخزين التوكن في Flutter بشكل آمن.
- عدم تخزين كلمة المرور نهائيًا في التطبيق.
- تشفير كلمات المرور باستخدام Laravel Hash.
- تفعيل التحقق من البريد الإلكتروني لاحقًا.

## 2. الصلاحيات

- لا يتم الاعتماد على واجهة Flutter في منع الوصول.
- كل صلاحية مهمة يجب التحقق منها داخل Backend.
- المستخدم العادي لا يستطيع الوصول لمسارات الإدارة.
- المرشد لا يستطيع عرض طلاب غير مرتبطين به.
- المعلم لا يستطيع تعديل دورات لا يملك صلاحيتها.
- Admin فقط يستطيع إدارة الأدوار والصلاحيات.

## 3. حماية API

- استخدام `auth:sanctum` للمسارات الخاصة.
- استخدام Rate Limiting لمنع المحاولات الكثيرة.
- التحقق من صحة البيانات عبر Form Requests.
- منع إرسال حقول غير مسموحة.
- عدم إرجاع بيانات حساسة في JSON.

## 4. حماية الملفات

- تحديد أنواع الملفات المسموحة.
- تحديد الحد الأقصى لحجم الملف.
- عدم تنفيذ أي ملف مرفوع.
- تخزين الملفات في مكان آمن.
- استخدام روابط مؤقتة للملفات الخاصة لاحقًا.
- تخزين الفيديوهات على Cloud Storage في الإنتاج.

## 5. حماية الدروس المدفوعة

- لا يتم الاعتماد على Flutter فقط في إخفاء الدرس.
- Backend يجب أن يتحقق من:
  - هل المستخدم اشترى الدورة؟
  - هل الدرس مجاني؟
  - هل الدرس السابق مكتمل؟
  - هل الحساب نشط؟
- روابط الفيديوهات المدفوعة يجب ألا تكون عامة في الإنتاج.

## 6. المدفوعات

- لا يتم اعتبار الطلب مدفوعًا من التطبيق مباشرة.
- يجب تأكيد الدفع من بوابة الدفع أو webhook.
- تسجيل كل عملية دفع.
- عدم حذف سجلات الطلبات والمدفوعات.
- مراجعة حالات الاسترجاع والطلبات الفاشلة.

## 7. المحادثات

- المستخدم لا يستطيع قراءة محادثة ليس مشاركًا فيها.
- المرشد لا يستطيع مراسلة طالب غير مرتبط به إلا بصلاحية.
- الملفات داخل المحادثات يجب فحصها وتحديد نوعها.
- يمكن لاحقًا إضافة نظام بلاغات للمحادثات.

## 8. المجتمع

- يجب مراجعة المحتوى المخالف.
- دعم البلاغات على المنشورات.
- إمكانية إخفاء أو حذف المحتوى.
- منع السبام عبر Rate Limiting.
- حفظ سجل عمليات الإدارة المهمة.

## 9. الذكاء الاصطناعي

- المساعد لا يصدر فتاوى حساسة.
- الأسئلة الحساسة تحول إلى مرشد أو مختص.
- يجب تسجيل الأسئلة العامة لتحسين الخدمة.
- عدم إرسال بيانات حساسة للمساعد دون حاجة.

## 10. لوحة الإدارة

- حماية لوحة الإدارة بتسجيل دخول.
- تفعيل صلاحيات دقيقة لكل Resource.
- تسجيل العمليات الحساسة.
- عدم إعطاء صلاحية Admin إلا للمستخدمين الموثوقين.
- استخدام كلمة مرور قوية.

## 11. حماية البيئة

- عدم رفع ملف `.env` إلى Git.
- عدم وضع مفاتيح API داخل Flutter مباشرة إذا كانت حساسة.
- استخدام متغيرات بيئة في السيرفر.
- تغيير مفاتيح الوصول عند الشك في تسريبها.

## 12. النسخ الاحتياطي

- نسخ احتياطي يومي لقاعدة البيانات في الإنتاج.
- نسخ احتياطي للملفات المهمة.
- اختبار استعادة النسخ الاحتياطية.
- حفظ النسخ الاحتياطية خارج نفس السيرفر.

## 13. السجلات والمراقبة

- تسجيل أخطاء Backend.
- استخدام Sentry أو أداة مشابهة لاحقًا.
- مراقبة محاولات الدخول الفاشلة.
- مراقبة رفع الملفات.
- مراقبة أخطاء الدفع.

## 14. قاعدة ذهبية

لا تثق أبدًا في التطبيق.

كل شيء مهم يجب التحقق منه داخل Backend:

- الصلاحيات
- الدفع
- إكمال الدروس
- فتح الدروس
- إرسال الرسائل
- الوصول للملفات
- إدارة الطلبات
